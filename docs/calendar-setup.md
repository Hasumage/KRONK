# Подключение календаря

Математика работает независимо. Для сценария «занесу в календарь» используются OpenAI для понимания переписки и Google Calendar API для записи события. Premium и Telegram api_id/api_hash не нужны.

## Что делает сценарий

Собеседник пишет «29 октября, 18:30, встречаемся…». Владелец пишет «занесу в календарь», «добавлю эту встречу в календарь» или аналогичное намерение. Код проверяет явный календарный маркер, автора и направление; только затем отдельный извлекатель получает короткий контекст и возвращает параметры события. IDs источников и свидетельство команды формируются приложением из реальных сообщений, а не генерируются моделью. Обычное согласие, отказ от посещения, процитированная чужая фраза и сообщения собеседника не запускают запись и не отправляются на классификацию. Неопределённое событие вызывает уточнение в личке, а не молчаливое игнорирование. Собеседнику подтверждение не отправляется.

После успешной записи бот пишет владельцу в свой обычный личный чат: «✅ Занесено в календарь», название, дата/время, место, напоминание и ссылка. Неизвестные дата/время вызывают уточнение там же. Ответить можно через Reply на вопрос бота или `/clarify ID текст`. При неизвестном адресе место не выдумывается. Если длительность не указана, применяется 60 минут с пометкой в уведомлении. Reminder — за 60 минут, timezone по умолчанию Europe/Moscow.

До подключения Google бот сообщает только, что событие пока не создано и какие настройки отсутствуют. Повторно обрабатывать старую фразу после подключения он не будет — нужно написать новую. Текущий этап поддерживает только создание: другие намерения отбрасываются.

### Неформальные варианты

Можно писать, например: «закину в календарь», «щас забью в календарь», «вобью в календарик», «впишу себе», «отмечу у себя», «помечу себе», «зафиксирую у себя», «забью встречу», «запланирую этот созвон». Для коротких фраз без слова «календарь» особенно важен Reply на приглашение или понятный недавний контекст. Они не заменяют дату и время: если параметров не хватает, бот уточнит их в личке.

«Ок, буду» остаётся обычным согласием. «Не впишу себе», «забью на встречу», цитирование команды, «уже добавил в календарь», «запишу себе номер телефона» и «отмечу у себя в задачах» не запускают создание события.

## Где получить Google Client ID и Client Secret

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) под тем Google-аккаунтом, календарь которого нужен.
2. В выборе проекта сверху нажмите **New project / Создать проект**, название `KRONK`. Можно использовать существующий подходящий проект.
3. Откройте [страницу Google Calendar API](https://console.cloud.google.com/apis/library/calendar-json.googleapis.com) в этом проекте и нажмите **Enable / Включить**.
4. Откройте **Google Auth platform → Branding**. Если появится **Get Started**, заполните название приложения `KRONK`, свой контактный email. Для обычного личного Gmail выберите аудиторию **External / Внешняя**. Для внутреннего Workspace-приложения администратор может разрешать **Internal**.
5. В разделе **Audience → Test users** добавьте email аккаунта, календарь которого будете подключать, пока приложение в режиме Testing. В **Data Access** при необходимости добавьте scope `https://www.googleapis.com/auth/calendar.events`.
6. Откройте **Google Auth platform → Clients → Create client**. Тип приложения: **Desktop app / Приложение для компьютеров**, имя `KRONK Desktop`.
7. После создания получите **Client ID** и **Client secret** (или скачайте JSON). Внесите их в локальный `.env`:

```dotenv
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_CALENDAR_ID=primary
BUSINESS_CALENDAR_ENABLED=true
```

Не нужен отдельный Google API key. Публичный сайт для Desktop app не требуется. Импорт JSON с credentials в Git запрещён; безопасное место для него — игнорируемый каталог `data/`.

Пошаговая официальная инструкция: [Google Calendar Node.js quickstart](https://developers.google.com/workspace/calendar/api/quickstart/nodejs). Loopback OAuth и PKCE описаны в [Google OAuth for Desktop Apps](https://developers.google.com/identity/protocols/oauth2/native-app). Наш flow запрашивает `calendar.events`, а не read-only scope из демонстрационного quickstart.

## Одноразовая авторизация

Сначала остановите фоновый процесс, чтобы авторизация не открывала рабочую SQLite параллельно с обработкой сообщений:

```powershell
./scripts/stop-business.ps1
npm run build
npm run business:oauth
```

Команда напечатает ссылку входа Google. Откройте её, выберите нужный Google-аккаунт и разрешите доступ. Callback слушает только `http://127.0.0.1:8765/callback`, защищён state и PKCE. После успеха токены хранятся зашифрованно в BUSINESS_DATABASE_PATH под BUSINESS_ENCRYPTION_KEY. Пароль Google и коды не нужно передавать боту или в переписку.

Затем снова запустите:

```powershell
./scripts/start-business.ps1
```

Проверьте `/calendar` в личке бота: должно быть «Календарь: подключён». При смене прав/истечении refresh token OAuth нужно повторить. Внешнее приложение в режиме Testing может требовать периодической повторной авторизации согласно политике Google.

## OpenAI

В `.env` нужны OPENAI_API_KEY, OPENAI_MODEL и актуальные цены ввода/вывода на миллион токенов для выбранной модели. Модель и цены оператор задаёт самостоятельно. Бюджет по умолчанию 5 USD в месяц резервируется консервативно до каждого запроса.

Источник: [официальная документация OpenAI по модели и ценам](https://developers.openai.com/api/docs/models/gpt-5.4-mini). Локальная проверка токена и доступности модели: `node scripts/check-openai.mjs`. Проверка семантики на синтетических примерах с небольшим расходом API: `node scripts/check-calendar-ai.mjs` после сборки.

## Проверка на реальном чате

Чат должен быть доступен боту в настройках «Автоматизация чатов». До запуска бот не читает старую историю: используйте новую переписку либо Reply на исходное приглашение. Напишите «занесу в календарь» со своего аккаунта, дождитесь подтверждения в отдельном чате с ботом и проверьте само событие в Google Calendar. Простое «да, буду» и фраза собеседника не должны создавать событие.
