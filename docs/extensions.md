# Дополнительные модули

Ядро работает автономно. `BUSINESS_EXTENSION_ENTRY` по умолчанию пуст; при необходимости оператор может указать путь к собранному JavaScript-модулю. Его default export принимает `ExtensionContext` и возвращает массив `BusinessExtension` из `src/extensions/business.ts`.

Хуки: приём сообщения, команды владельца, callback, состояние, фоновая обработка и очистка. Дополнительные команды включаются в меню владельца. `receive=true` означает, что сообщение занято сценарием расширения: обычный автоматический ответ и математика его не перехватят. Основные явные команды календаря, задач и документов продолжают обрабатываться. Остальные хуки необязательны.

Путь задаётся только оператором в конфигурации, не через сообщения Telegram. Расширение исполняет доверенный локальный код с доступом к сервисам процесса; не подключать модули из неизвестных источников. Проверка прав владельца, паузы, разрешений и защита от повторов остаются обязанностью расширения.

Локальные дополнительные исходники можно держать в `src/private/`: этот каталог исключён из Git и Docker-контекста. TypeScript соберёт их локально вместе с проектом. Расширения могут применять собственные миграции через `Store.migrate(directory)`; имена миграций должны быть уникальны. Данные и секреты размещаются только в игнорируемом `data/` и переменных окружения.

Публичная сборка и тесты не требуют локальных модулей. Для проверки перед публикацией экспортировать только файлы Git-индекса и запускать проверки на таком экспорте.
