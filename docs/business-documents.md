# Документы через Автоматизацию чатов

Работает в подключённых личных чатах через Bot API, без Telegram Premium и без MTProto. Модуль включается флагом `BUSINESS_DOCUMENTS_ENABLED=true`; нужен настроенный OpenAI. Google Calendar для документов не требуется.

Владелец отвечает **Reply именно на файл**: «изучу», «гляну», «посмотрю условия», «разбери договор», «надо посмотреть условия», «дай выжимку». Для короткой фразы нужна привязка к файлу. Чужое сообщение, обычная загрузка, отрицание, цитата и условное обещание не разрешают обработку. Если файла нет, бот объяснит в личке, как его указать; соседний файл наугад не выбирается.

В личке бота можно загрузить файл с подписью «разбери» либо ответить на него `/analyze`. Загрузка без подписи сама по себе не запускает анализ.

## Выжимка

После принятия запроса бот отдельно подтверждает очередь. Готовая выжимка содержит применимые к документу разделы: предмет, обязанности, суммы/оплата, сроки, необычные условия, возможные риски и вопросы для уточнения. Риски обозначены как выводы помощника. Каждый факт и риск сопровождается дословной цитатой со страницей PDF или абзацем DOCX/TXT; приложение проверяет наличие цитаты в указанном фрагменте. Это проверка источника, а не доказательство правильности всей интерпретации. Юридическая безопасность документа не подтверждается.

Результат отправляется **только владельцу в личку**, без `business_connection_id`. Длинные результаты делятся на части. При сбое или неподтверждённых цитатах бот не сообщает об успешном разборе.

## Комментарий владельца и профессиональная оценка

После «гляну» можно дописать свободное задание: «гляну и дам комментарии по презентации, идее и стилю», «гляну и сравню с конкурентами», «гляну и скажу, что сократить для MVP». Бот сохраняет фокус запроса в зашифрованной очереди и помимо выжимки выдаёт отдельные комментарии: наблюдение, основание и конкретное предложение по улучшению. Наличие слов «не надо» или «задачи» внутри такого комментария не отменяет явное начальное намерение «гляну». Максимальная длина сообщения — 2000 символов; слишком длинный запрос отклоняется с объяснением.

По умолчанию выполняется нейтральный разбор содержания, структуры и ясности. Роль для оценки можно задать через `DOCUMENT_REVIEW_PERSONA`, без выдумывания личного опыта или вкусов владельца. Комментарии зависят от запроса, предложения отделены от фактов. В конце приходит черновик ответа собеседнику от первого лица; бот отправляет его только владельцу, а владелец решает, использовать ли текст.

Для запроса про визуальный стиль PDF локально отрисовывается в PNG в отдельном процессе. По умолчанию выбирается до 8 равномерно распределённых страниц, включая первую и последнюю, с ограничением `DOCUMENT_VISUAL_MAX_PAGES` (максимум 12). Модель получает эти изображения, а бот перечисляет просмотренные страницы. Визуальный комментарий может ссылаться только на реально переданную страницу. Изображения обрабатываются в памяти, не сохраняются в историю или на диск. Дополнительные изображения расходуют входные API-токены; оценка бюджета учитывает их отдельно.

Для DOCX/TXT оцениваются содержание и техническая сторона; оформление не приписывается невидимому макету. Презентацию PowerPoint нужно экспортировать в PDF. Короткое «гляну» без дополнительного задания сохраняет обычный текстовый разбор.

## История и удаление

- `/docs` — последние десять сохранённых разборов.
- `/doc 12` — повторно показать выжимку без нового вызова модели.
- `/forget_doc 12` — удалить локальную выжимку и её копии в локальном outbox. Уже отправленные сообщения Telegram остаются в чате; их можно удалить средствами Telegram.

Результаты хранятся зашифрованно `DOCUMENT_RETENTION_DAYS` дней (по умолчанию 7), затем удаляются вместе с локальными копиями. Файл и извлечённый текст не записываются на диск. Идентификатор загрузки хранится зашифрованно в очереди до окончания работы и затем очищается. Минимальный ключ дедупликации остаётся: повторный update не запускает анализ заново. Зашифрованные резервные копии имеют отдельный срок хранения.

## Ограничения

| Настройка                    | По умолчанию                                        |
| ---------------------------- | --------------------------------------------------- |
| `MAX_DOCUMENT_BYTES`         | 5 000 000 байт                                      |
| `MAX_DOCUMENT_PAGES`         | 50 страниц PDF                                      |
| `MAX_DOCUMENT_CHARS`         | 100 000 символов извлечённого текста                |
| `DOCUMENT_MAX_OUTPUT_TOKENS` | 6 000 токенов ответа                                |
| `DOCUMENT_RETENTION_DAYS`    | 7 дней                                              |
| `DOCUMENT_VISUAL_MAX_PAGES`  | 8 страниц для визуальной выборки                    |
| `DOCUMENT_REVIEW_PERSONA`    | Нейтральный разбор содержания, структуры и ясности. |

Поддерживаются PDF с текстовым слоем, DOCX без макросов и TXT UTF-8/UTF-16 с BOM. PDF с паролем, повреждённые файлы и неподдерживаемые форматы завершаются понятной ошибкой. Для DOCX надёжного количества страниц нет: используются лимиты байт и текста, ссылки на абзацы.

Текст не обрезается молча: превышение лимита останавливает работу до отправки текста модели. Обычный текстовый разбор скана требует OCR, он пока не подключён. При визуальном запросе страницы PDF без текстового слоя можно оценить по изображениям; дословные цитаты с них не подтверждаются, и бот отмечает ограничение. Непросмотренные страницы не получают визуальную оценку. Сложные таблицы могут терять структуру при извлечении текста.

Загрузка разрешена только с Telegram, поток ограничен по фактическому размеру, перенаправления запрещены. Извлечение выполняется отдельным процессом с ограничением памяти 128 МБ и времени 15 секунд; отрисовка — в отдельном процессе с heap 256 МБ, временем 30 секунд, ограничением пропорций страниц и суммарного размера изображений. Секреты окружения этим процессам не передаются. Макросы и команды из документа не исполняются. Модели отправляются текст документа, задание владельца, профессиональная роль и, при визуальном запросе, изображения выбранных страниц; переписка и идентификаторы Telegram не отправляются. Используется `store=false`. Настройки обмена данными API-организации действуют отдельно.

Сохраняются общий месячный лимит API и проверки паузы/dry-run. Внутренний бюджет считает консервативную верхнюю оценку платной стоимости, даже если провайдер применяет бесплатные токены. Участие в программе и реальные списания проверяются в OpenAI Platform, бот их не определяет. Платные инструменты поиска или OCR не используются.

## Проверка

`npm run verify` проверяет очереди, владельца, привязку Reply, дедупликацию, паузу, восстановление, историю/удаление, цитаты, ограничения загрузки и реальные процессы извлечения PDF/DOCX/TXT.

`node scripts/check-document-analysis.mjs` после сборки проверяет реальный OpenAI на синтетическом TXT с суммой, сроком и встроенной вредоносной инструкцией. Расходует API-токены; в Telegram ничего не отправляет и рабочую БД не меняет.

`node scripts/check-document-review.mjs` проверяет реальную модель на текстовом запросе с ролью разработчика/дизайнера и на слайде PDF с известным визуальным оформлением, проверяет комментарии, основания и черновик ответа. Также расходует API-токены без отправок в Telegram.
