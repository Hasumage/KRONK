# Реализация и приёмка

1. Архитектура: ADR, модель угроз, схема данных, контракты TypeScript.
2. Инфраструктура: конфиг Zod, шифрование, SQL-миграции, очередь, health, логи, Docker/Compose.
3. Telegram и намерения: GramJS ingest, Reply-контекст, mock fixtures и OpenAI Structured Outputs, policy, dry-run.
4. Calendar: локальный OAuth PKCE/state, сохранение токенов, stable event ID, reminder, update/cancel и outbox.
5. Задачи: Reply-создание, nullable срок, закрытие и уточнения, /tasks.
6. Автоответы: opt-in, темы/чаты, ночное окно, owner pause, cooldown, лимиты, текст из проверенной KB.
7. Регистрация: ограниченный Chromium, DNS-pin proxy, локальный предпросмотр, подтверждение/отмена, TTL, ручное завершение неподдерживаемых форм.
8. Документы: процесс извлечения TXT/DOCX/PDF, ограничения, выжимка и owner outbox. OCR отдельно, не реализован.
9. Проверка: TypeScript, unit/integration mock-потоки, сборка, автономная демонстрация, ручной live-чек-лист.

## Перед реальным использованием

- Выбрать отдельный тестовый Google Calendar и тестовый Telegram-диалог.
- Создать ключ, авторизовать аккаунт, проверить owner ID и адресата бота.
- Начать с MODE=live / DRY_RUN=true: Telegram и OpenAI работают, исходящих действий нет. Проверять `npm run inspect` при остановленном процессе.
- Для live отключить DRY_RUN осознанно, сначала оставить только Calendar и задачи. `/pause` должен останавливать новые исполнения.
- Прогнать фразы: обычное согласие, явное намерение, отказ, неизвестная дата, неоднозначные задачи, повтор update, сетевой сбой после создания.
- Сверить timezone, событие и reminder за 60 минут в Google UI. Проверить update/cancel на тестовом событии.
- Автоответы включать после проверки KB: личное сообщение → молчание; рабочий вопрос ночью → один маркированный ответ; вмешательство владельца → пауза.
- Для формы проверить домен, все значения и TTL, сначала отменить. Подтверждать только тестовую бесплатную форму. Не считать HTTP 200 доказательством регистрации.
- Для документов проверить TXT/DOCX/PDF, скан, большой/повреждённый файл и injection. Выжимка должна попасть только владельцу.
- Проверить backup/restore, retention и удаление. Проверить uncertain после аварийной остановки.

Реальные интеграции без пользовательских ключей не считаются проверенными. Автономные тесты проверяют код на mock-провайдерах и изолированных файлах; это не замена live-проверке доступа и качества классификации.
