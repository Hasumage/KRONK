# Основа рабочих автоответов — выключена

Модуль для Business Bot API выключен по умолчанию: `BUSINESS_REPLY_ENABLED=false`. Рабочую базу знаний, разрешённые темы и включение настраивает владелец.

Пожелания для будущего запуска сохранены в настройках по умолчанию: все доступные боту личные чаты, включая новые (`BUSINESS_REPLY_SCOPE=all`), круглосуточно (`BUSINESS_REPLY_SCHEDULE=always`). Доступ ограничен настройками «Автоматизации чатов» Telegram; группы и недоступные боту диалоги не охватываются.

## Контракты и база знаний

- `src/replies/knowledge.ts` проверяет формат и отбирает одобренные записи включённых тем с неистёкшим сроком.
- `src/adapters/reply-ai.ts` выбирает идентификаторы подходящих ответов. Модель не формулирует произвольный текст для собеседника.
- `src/replies/service.ts` контролирует разрешения, очередь, ограничения частоты, паузы, актуальность, предпросмотр и доставку.
- `migrations/005_business_replies.sql` добавляет отдельные таблицы; к работающей БД эта миграция в ходе подготовки не применяется.

Шаблон: `fixtures/auto-reply-knowledge.example.json`. В нём есть отключённая тема `project` без готовых ответов. Рабочий путь — `data/auto-reply-knowledge.json` (не включается в Git). Для записи потребуются:

| Поле        | Назначение                                                    |
| ----------- | ------------------------------------------------------------- |
| `id`        | Уникальный идентификатор записи                               |
| `question`  | Какой рабочий вопрос покрывает готовый ответ                  |
| `answer`    | Проверенная формулировка, которую можно отправить собеседнику |
| `source`    | Источник и основание фактов                                   |
| `approved`  | Явное одобрение владельцем                                    |
| `expiresAt` | ISO-время окончания действия или явное `null`                 |

Тема также имеет `id`, `title`, `enabled` и массив `entries`. Отключённые темы, неодобренные и просроченные записи исключаются. Повторные ID и неверные данные блокируют загрузку. При отсутствии базы модель не вызывается. Перечитывание ошибочной базы отключает выбор ответов и отменяет устаревшие варианты.

## Будущий режим проверки

`BUSINESS_REPLY_MODE=preview` по умолчанию. Подходящий рабочий вопрос приводит к **варианту только в личку владельца** с текстом ответа, основанием и кнопками «Отправить этот ответ», «Пропустить», «Пауза в этом чате». Кнопка отправки — отдельное подтверждение конкретного текста; глобальный выключатель, актуальность базы и состояние чата всё равно проверяются.

Для самостоятельной отправки предусмотрен отдельный режим `live`. Оба режима требуют явного включения модуля. Снятие паузы и разрешение отдельного чата не меняют глобальный выключатель.

Готовый ответ собирается из 1–2 одобренных записей одной темы, без придумывания ссылок и обещаний. В начале всегда стоит «Я ИИ-помощник». Модель должна выбрать `ignore` для личного общения, неизвестных условий и неоднозначности. Даже высокая уверенность не разрешает неизвестный ID, смешение тем или использование просроченного факта. Это ограничивает содержание, но качество семантического выбора ещё потребуется проверить на будущих реальных материалах до самостоятельной отправки.

## Диалог и ограничения

- Сообщения одной серии объединяются с задержкой 10 секунд, максимум 30 секунд от начала серии, 8 сообщений / 3000 символов. Переполнение отменяет серию без ответа по обрезанному тексту.
- При любом вмешательстве владельца ответы в чате приостанавливаются на `AUTO_REPLY_OWNER_PAUSE_MINUTES` (по умолчанию 120 минут). Собственные ответы бизнес-бота не считаются вмешательством.
- Новое сообщение делает ранее подготовленный вариант неактуальным, включая сообщения во время классификации и проверки подключения. Во время cooldown новый вариант может не появиться; устаревший автоматически не отправляется.
- Cooldown по умолчанию 30 минут, до 5 подготовленных ответов в день на чат. Действует общий `MAX_MESSAGES_PER_DAY` и существующий месячный бюджет API.
- Старые сообщения не получают запоздалых ответов. Вариант для подтверждения действует 10 минут.
- Перед отправкой заново проверяются владелец подключения, его состояние и `can_reply`. Ответ привязан к последнему сообщению серии через Reply.
- Явный 429 допускает повтор после указанной задержки. Неоднозначная сетевая отправка переходит в `uncertain` и не повторяется; владелец получает уведомление для ручной проверки.

В будущем доступны команды только владельцу в личке бота: `/replies`, `/reply номер`, `/reply_pause номер|all`, `/reply_resume номер|all`, `/reply_block номер`, `/reply_allow номер`, `/reply_reload`. Они не включают выключенный модуль. Индивидуальные исключения сохраняются при переходе к охвату всех чатов; режим `selected` использует отдельное явное разрешение.

## Хранение и проверка

Вопросы, готовые ответы и имена чатов зашифрованы. В модель передаются только ограниченная серия сообщений и релевантные записи базы, без имён чатов и идентификаторов Telegram. После retention содержимое очереди удаляется, минимальные ключи дедупликации сохраняются. Разрешения и паузы чатов хранятся как настройки.

`npm run verify` проверяет выключенный модуль, общий охват и расписание, отсутствие знаний, сбор серии, вмешательство владельца, отмену устаревших вариантов, защиту подтверждения, права подключения, лимиты, 429, сетевую неоднозначность и восстановление. Тесты используют вымышленную учебную базу и подменённый API в изолированных БД; реальные сообщения собеседникам и платные API-запросы не выполняются.
